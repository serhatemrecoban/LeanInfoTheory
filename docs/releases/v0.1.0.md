# LeanInfoTheory v0.1.0

Release date: **2026-09-01**

`v0.1.0` is the first public-library release of LeanInfoTheory, a Lean 4 and
mathlib foundation for reusable finite discrete information theory. It
establishes the source-compatibility baseline for the `0.1.x` line. Its scope is
deliberately foundational: this release does not claim a complete formalization
of information theory or of any particular textbook or research paper. The API
is not permanently frozen.

## Mathematical scope

The release includes:

- finite `PMF` support, map, bind, mixture, marginal, product, and raw-channel
  utilities;
- entropy, conditional entropy, mutual information, conditional mutual
  information, random-variable forms, and pair/triple/family chain rules;
- entropy bounds and equality cases, finite Fano inequalities, finite-family
  submodularity and subadditivity, and mutual-independence equality results;
- semantic conditional-law and expected-self-information views;
- PMF bridges to mathlib KL divergence, including support/finiteness, equality,
  log-sum, convexity, common-base conditional KL, and contraction results;
- ordinary and conditional independence, finite Markov structure, stochastic
  channels, posteriors, and data processing; and
- fixed-prior and model-family sufficiency, exact recovery, Fisher--Neyman
  factorization, and guarded KL-preservation characterizations.

The mathematical development draws on standard references, including Thomas M.
Cover and Joy A. Thomas, *Elements of Information Theory* (John Wiley & Sons,
1991). See the
[foundation conventions](https://github.com/serhatemrecoban/LeanInfoTheory/blob/v0.1.0/docs/foundation-conventions.md)
for the broader reference set and the conventions used when adapting textbook
statements to Lean and mathlib.

## Information units

Canonical `Real`-valued entropy and information quantities are measured in
nats because the underlying mathlib APIs use natural logarithms.
`LeanInfoTheory.Shannon.Units` provides opt-in scalar conversions
`natsToBase` and `natsToBits`; there is no duplicate bit-valued theorem
hierarchy.

Mathlib KL divergence remains canonically `ENNReal`-valued and may be infinite.
Real-valued KL consequences retain support, absolute-continuity, or finiteness
guards because `ENNReal.toReal ⊤ = 0` is not a finite KL value.

## Compatibility, installation, and imports

LeanInfoTheory `0.1.0` is toolchain-fixed at Lean 4 and mathlib `v4.33.1`.
Add the immutable tag to a compatible Lake project with:

```toml
[[require]]
name = "LeanInfoTheory"
git = "https://github.com/serhatemrecoban/LeanInfoTheory"
rev = "v0.1.0"
```

- `import LeanInfoTheory` selects the lightweight mathematical root.
- `import LeanInfoTheory.Shannon` selects the complete supported umbrella.
- Focused imports remain preferable when import weight matters.

The frozen baseline contains 31 supported modules, 601 project-owned public
declarations, 92 lightweight-root exports, and 94 reviewed `simp`
declarations. Examples, `Basic`, and `MathlibFragments` are maintained but
non-stable. See the
[README](https://github.com/serhatemrecoban/LeanInfoTheory/blob/v0.1.0/README.md)
and the
[`v0.1.x` public API contract](https://github.com/serhatemrecoban/LeanInfoTheory/blob/v0.1.0/docs/v0.1-public-api.md).

Throughout `0.1.x`, supported names, module paths, namespaces, signatures,
assumptions, documented semantics, root exports, and reviewed attributes are
intended to remain source-compatible. Patch releases may add declarations or
aliases; a necessary breaking change belongs in a later minor release such as
`0.2.0`.

## Validation and trust

The release snapshot passes the maintained routine suite: default and
warning-as-error builds, all supported direct-import checks, the frozen API,
root-export and `simp` audits, the all-project axiom audit, five independently
compiled README examples, strict proof-placeholder and implementation-shortcut
scans, generated-artifact and website checks, and repository hygiene. It is
also reproduced from a clean exact checkout and compiled through a minimal
external Lake consumer.

The separate signature-bearing documentation gate covers all 31 supported
module pages and all 601 declarations, checks the 92 canonical exports,
excludes all 13 non-stable modules, and generates zero optional equation rows.
Release-mode staging binds project source links to the exact release commit,
validates the complete Pages artifact, and does not deploy it. Routine CI and
the nonpublishing API-documentation/Pages capacity gates provide the remote
evidence recorded in the release handoff.

The only approved axioms are `propext`, `Classical.choice`, and `Quot.sound`.
Lean's kernel establishes derivability from the formal assumptions; it does not
by itself establish that a statement, convention, or interpretation matches
the intended mathematics. The project does not claim a manual line-by-line
audit.

## Limitations

This release focuses on finite discrete information theory. It does not yet
provide general measurable or continuous entropy, entropy rates or a
stochastic-process hierarchy, channel capacity or coding theorems,
AEP/typicality, a dedicated finite-`PMF` total-variation API or Pinsker
inequalities, full majorization/Birkhoff theory, or canonical/minimal sufficient
statistics. Some supported theorems intentionally retain stronger finite-type
assumptions, as documented in the public API contract. Application-specific
certificate tooling and paper-specific constructions are developed in separate
downstream projects rather than included in this general-purpose library.

## AI-assisted development

Development used substantial AI coding-agent assistance, primarily OpenAI
Codex and ChatGPT. AI-generated code is treated as untrusted until it passes
Lean and project validation. The project does not claim manual authorship of
the proof code or a manual line-by-line audit. Human responsibility remains for
scope, theorem statements, assumptions, conventions, architecture, review, and
mathematical interpretation. See the
[README disclosure](https://github.com/serhatemrecoban/LeanInfoTheory/blob/v0.1.0/README.md#ai-assisted-development)
for the complete statement.
