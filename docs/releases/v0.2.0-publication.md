# LeanInfoTheory v0.2.0

Release date: **5 November 2026**.

LeanInfoTheory's second release expands the finite information-theory library
from 601 supported declarations in 31 modules to **811 declarations in 57 modules**.
The lightweight root retains its 92 aliases. The library remains based on
mathlib's finite probability distributions, with Lean and mathlib pinned to
**v4.33.1**.

## New mathematical coverage

- **Quantitative probability and continuity:** total variation, event and
  bounded-test characterizations, maximal couplings, channel and coordinate
  transport, Markov gluing, Pinsker's inequality, quantitative independence,
  continuity bounds for entropy and information, and finite-PMF topology.
- **Independent products and iid blocks:** finite dependent products, marginals,
  coordinate maps and block splitting, entropy and mutual-information product
  laws, and canonical KL product laws with their support and finiteness guards.
  Product channels have arbitrary-input upper bounds and equality for independent
  inputs; a product alphabet alone does not imply independence.
- **Finite-iid source coding:** weak AEP, strict typical sets, deterministic
  fixed-length codes, and vanishing-error achievability at every rate strictly
  above entropy. The source strong converse gives error tending to one for
  positive-message-budget families under an eventual rate cap strictly below
  entropy. The operational source threshold is an infimum statement; it does
  not assert attainment at the entropy rate.
- **Finite-channel capacity and converses:** attained mutual-information capacity
  for a nonempty finite input alphabet, product capacity, and noiseless, constant,
  binary-symmetric and erasure-channel formulas. Fano-based finite bounds and
  asymptotic weak converses concern actual deterministic block-code families,
  uniform-message average error and their stated rates. Eventual and
  infinitely-often above-capacity gaps retain distinct conclusions.

Information and rates use **nats**. Bits require explicit conversion. Statements
retain their finite-alphabet, support, nonemptiness, positive-message-budget and
block-length hypotheses. Null conditional fibers use documented fallback rows;
these rows have no asserted probabilistic interpretation on null events.

Channel-coding achievability, operational channel-capacity equality and a channel
strong converse remain outside this release. The library does not claim a full
formalization of information theory, continuous or differential entropy, or an
efficient executable encoder.

## Installation and compatibility

In a compatible Lake project, pin the release explicitly:

```toml
[[require]]
name = "LeanInfoTheory"
git = "https://github.com/serhatemrecoban/LeanInfoTheory"
rev = "v0.2.0"
```

`import LeanInfoTheory` selects the lightweight foundation.
`import LeanInfoTheory.Shannon` selects the full supported mathematical stack;
focused modules remain separately importable.

The original v0.1.0 release and its documentation remain available unchanged.
No breaking API migration is selected. Validation compares both the original
601-declaration surface and the complete 811-declaration retained surface,
including elaborated types, ownership, import boundaries, root exports and
reviewed attributes. Exact type compatibility alone does not prove unchanged
definition bodies or mathematical semantics.

## Perfect Functional Representations case study

[PerfectFunctionalRepresentationsLean](https://serhatemrecoban.github.io/PerfectFunctionalRepresentationsLean/)
formalizes the definitions and main results of *On Perfect Functional Representations*,
within its documented finite-alphabet, support and auxiliary-variable qualifications.
It was completed using unchanged LeanInfoTheory v0.1.0, with paper-specific
constructions kept downstream. It demonstrates historical library reuse.

This case study illustrates how a downstream formalization can reuse information
identities while keeping paper-specific definitions and constructions in its own
project. That historical dependency and the independent compatibility validation
of v0.2.0 are distinct evidence.

## Documentation and trust

The [project website](https://serhatemrecoban.github.io/LeanInfoTheory/) keeps its
existing address. The new API snapshot is prepared for a separate Pages site so
its complete dependency documentation and search data can remain together.
The website update follows the GitHub release; until it is deployed, the main
site may still identify v0.1.0 as stable. The historical
[v0.1.0 API](https://serhatemrecoban.github.io/LeanInfoTheory/docs/v0.1.0/)
remains available.

Lean's kernel checks the formal declarations. Release validation rejects proof
placeholders and checks builds, maintained examples, supported imports, retained
APIs and allowed axioms. This is not a claim of manual line-by-line audit or a
guarantee that every formal statement captures every intended informal meaning.

Development used extensive assistance from AI coding agents. AI-generated code
is treated as untrusted; human responsibility remains for mathematical scope,
interpretation, review and release decisions. AI systems are not software authors.
