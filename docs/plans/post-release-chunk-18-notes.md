## 5. Concrete regression design and useful downstream pressure

The C16 paired-product support regression was explicitly deferred in its notes
Section 9 and handoff remaining-work table. Use two Boolean coordinates:
P=(fair,pure false), Q=(pure false,fair). The all-false word is in both supports;
(true,false) is supported only by P, and (false,true) only by Q. Thus both support
inclusions fail. For D(P||Q), the first coordinate is top and the second is log 2.
Product KL is top, but the sum of coordinate toReal values is log 2, whereas
product toReal is zero. This simultaneously tests support orientation and the
nontrivial failure of unguarded Real summation. These calculations are planned
mathematical regressions, not yet Lean-certified new results.

C17 already has a noisy correlated-law fixture with all-false output mass 1/8
versus product-of-marginals mass 1/16. C18 must consume its information formula,
not count the existing atom calculation as a completed MI test. The duplicated
fair-bit identity channel gives explicit strictness. Constant output under the
same correlated input proves equality need not require input independence.
The parity output (U,V,U xor V) demonstrates the pairwise/mutual distinction if
the optional criterion is exported.

E2 directly exercises the general independent-pair theorem from the focused
semantic FiniteProduct import. Independent fair bits U,V give mutually
independent coordinate pairs (U,U) and (V,V), while each pair has MI log 2 and
the transported whole joint has MI 2 * log 2. This prevents an example suite
whose independent-pair MI terms all vanish. Existing `mutualInfo_map_diag` and
`mutualInfoOf_self` support the proposed calculations; no new compilation is
claimed. Retain the separate heterogeneous/nonidentical pair consumer: two fair
Boolean pairs alone do not test dependent alphabets or unequal component laws.

Singleton index and singleton alphabet are distinct boundary cases. E1 and K1
now explicitly use an actual singleton alphabet (for example PUnit) with zero
entropy/KL; C2 includes singleton outputs with zero MI under correlated inputs.
These cases refine existing example owners rather than creating public wrappers.

For independent sources, XOR is a different and decisive use: independent fair
bits with observation Y=U xor V give each coordinate MI zero and joint MI log 2.
Conditioning on Y makes the coordinates dependent, so a spurious conditional
product premise would rule out precisely the intended consumer.

C22's producer is the actual raw-channel objective upper bound for every input
word law, paired with equality at product inputs. A private generic coordinate
upper-cap consumer can assemble the block upper bound without any capacity
definition. C23's producer is the same result at `messageLaw.map encode`, including
supported collisions and correlated codewords. Existing `(a,b) ↦ (a,a)` channel
joint/extension consumers supply exact transports without coding definitions.

C16--C17's 29 additions already cover normalization, support, transport,
independence and raw channels. C18 should establish their usefulness through the

### Advisory coordinate-swap example and trigger

For independent fair X₀,X₁, the deterministic channel Y₀=X₁, Y₁=X₀ gives
I(X₀;Y₀)=I(X₁;Y₁)=0 but I((X₀,X₁);(Y₀,Y₁))=2 log 2. The same-coordinate
product-channel premise is missing: outputs depend on the other input coordinate.

general channel. It does not contradict C18's product-channel statement.
