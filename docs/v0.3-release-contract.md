## What was compared

Each checkout ran the warning-as-error build of `LeanInfoTheory.Shannon` under Lean 4.33.1. Each used its own previously compiled project modules. The reviewer checked the source and object hashes for all 77 supported modules against that checkout’s original evidence. Both checkouts then ran two fresh declaration exports and a fresh compiled import and attribute audit. The independent reviewer verified the original command records from both runs, their outputs and the 77 compiled project modules in each checkout. All four declaration exports matched the reviewer's separate compiler run on the Chunk 40 mathematical source, byte for byte. The audit results also matched after replacing each local compiled-file path with its module-relative path.

The comparison covered declaration names, module owners, source and compiled kinds, universe parameter order and full elaborated types. It checked the direct imports and transitive import closure of each supported module, the declarations and simp attributes available through each focused import, and name resolution through the root. The lightweight root has two direct project imports, five reachable project modules and 92 exported names. The complete surface has 94 reviewed simp entries. ## Source and qualification

The reviewer traced all 453 capture-tree files to their Git objects. All 168 tracked Lean files, including the library, examples and integration consumers, match the qualified Chunk 40 tree byte for byte. This checks the inherited definitions and proof bodies as well as their signatures. The two separate checkouts used the same nine pinned dependencies and the original structural exporter. Seven producer inputs differed from Chunk 40. Those changes set the package version and adapt capture, compatibility and metadata validation for the third release.

The release date is 26 November 2026. The capture binds the DOI-free candidate citation and the release-state file by their content hashes. Relative to the preceding capture, only the capture commit, capture tree and these two hashes changed in the contract. All compiled declaration records, import and attribute checks, the public manifest and the producer record are byte-identical across the two captures. Adoption of this contract and approval of the exact release diff are separate project-lead decisions. Qualification of the containing release commit requires its own clean build, compatibility and trust checks, both integration tests, external-consumer installation and API documentation qualification.

From a checkout containing the reviewed contract and approval envelope, substitute the full release commit in the first command. It reconstructs the original capture commit and verifies the recorded producer files. The second command rebuilds the compiled surface and compares it with the retained contracts.

```text
python scripts/reproduce_release3_checkpoint.py <full-release-commit>
python scripts/validate_development.py compatibility
```
