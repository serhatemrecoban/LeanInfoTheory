A foundation for your next formalization

LeanInfoTheory is a Lean 4 library that provides a reusable information-theoretic layer on top of mathlib. It currently covers finite discrete information theory.

Longer-term goal
Our goal is to help the information theory community build and maintain a shared library. We are developing LeanInfoTheory as one possible starting point for this effort, with definitions and theorems that others can reuse and extend. Whether the community builds on this project or develops another library, the needs that arise in formalizing papers should shape its coverage and interfaces.

Importance of a common library
Checking a formal proof does not by itself establish that its statement and definitions express the intended mathematics. Once the mathematical meaning of shared definitions and theorem statements has been reviewed, subsequent papers can reuse that review. This can reduce repeated checking of common foundations.

Install and prove your first result or explore the research-project guide. Help shape the library through the collaboration guide.

What is new in v0.3.0

Version 0.3.0 has 918 supported declarations across 77 modules, including 107 additions since v0.2.0. Three theorems illustrate what you can prove.

  • Neyman–Pearson testing. For two laws on a finite alphabet, a threshold test attains any prescribed false-alarm probability and maximizes power among tests of at most that size. It uses one rejection probability for all ties. Testing example
  • Operational channel capacity. For a finite memoryless channel with nonempty input alphabet, capacity is the least upper bound of rates achievable with vanishing uniform-message average error. The direct theorem gives a code family for each nonnegative rate strictly below capacity. Capacity and expurgation example
  • Lossless source–channel separation. A finite iid source can be reconstructed with vanishing block error when its entropy is strictly below channel capacity, using one channel use per source symbol. These theorems leave equality undecided. Separation example

The other three packages use information density to bound one-shot decoding error, bound the optimal binary prefix length in bits, and compute iid type-class probabilities from counts and KL divergence. See the focused imports or theorems and their assumptions.

Validation and Trust

Release declarations are checked by Lean's kernel and the maintained project builds. Continuous integration also regenerates the source-derived references and rejects proof placeholders in project Lean source.

Kernel checking establishes that formal declarations follow from their formal assumptions; theorem selection, assumptions, conventions, and mathematical interpretation remain human responsibilities.

Project Direction

The third release builds on the quantitative probability, coding and capacity results in the v0.2.0 API. For the original entropy and information-measure library, consult the v0.1.0 API or its archived source.

  • Implemented Total variation, maximal coupling, Pinsker bounds, continuity and finite probability topology.
  • Implemented Independent products, iid blocks and product-channel bounds for arbitrary inputs, with equality for independent inputs.
  • Implemented Finite-iid asymptotic equipartition, fixed-length source coding above entropy, and source-coding converses.
  • Implemented Attained information capacity, standard finite-channel examples and Fano-based channel weak converses.
  • Case study Perfect Functional Representations demonstrates reuse of unchanged v0.1.0 in a completed downstream formalization.
  • Published The first theorem blueprint chapter covers finite hypothesis testing and the exact-size Neyman–Pearson theorem. Download the v0.3.0 PDF.
  • Open A channel strong converse and the equal-entropy-and-capacity case of lossless separation remain open.

Collaboration guide

I welcome collaborators, whether you work in information theory, Lean, or both. You don't need a finished Lean proof to get involved.

  • Suggest a theorem. Open an issue with the mathematical statement, a reference if you have one, and how you would use it.
  • Plan a formalization. For a larger project, discuss the hypotheses and which existing results might help before starting the proof.
  • Improve an example or fix a bug. Small fixes can go straight to a pull request. The contributor section on GitHub links to the full guide, including setup and what to check.
